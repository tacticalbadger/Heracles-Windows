# Heracles for Windows

<img src="app/Heracles/Icon/Heracles.png" width="128" alt="The Heracles app icon: a notebook page with a heading, a checklist and lines of text">

A local-first, hierarchical notebook: pages in notebooks, a block editor, split panes and kanban boards. Everything is stored on your PC in one SQLite database.

This repository is the Windows app. It is a native app, written in C# (WPF) over the same Rust core as the [Mac app](https://github.com/tacticalbadger/Heracles), and it does what the Mac app does.

## Status and download

The native app is a preview. Builds are published on the [releases page](https://github.com/tacticalbadger/Heracles-Windows/releases): a disc image (an `.iso` file) for Windows on x64, and one for Windows on ARM. The app can also be [built from source](#building).

- **Nothing to install.** Double-click the `.iso` and Windows opens it as a disc. Copy the `Heracles` folder from it to a place of your own on your PC (`%LOCALAPPDATA%\Programs`, say), run `Heracles.exe` from the copy, and eject the disc. The .NET runtime is inside the folder. It needs Windows 10 version 2004 or later, or Windows 11.
- **The build is not code-signed.** Windows will say it does not recognise the app. Choose **More info**, then **Run anyway**.
- **From 0.3.0 on it updates itself.** It looks for a new version once a day and from **Help ▸ Check for Updates…**, shows what changed, and installs it when you agree. Installing restarts the app, after your notes are saved. **Check for Updates Automatically** turns the daily look off. An update is installed only if it carries the developer's signature. The app replaces its own folder, so the folder has to be somewhere it can change: run from the disc, it says that it cannot.
- Version 0.2.1 and earlier cannot update themselves. Put a current version in by hand once, and later ones arrive in the app.
- **Nobody has used it day to day yet.** It passes its automated tests and its scripted checks of the real window, one of which uses a real mouse and keyboard for a minute. That is not a person using it. What has been checked and what has not is written down, plainly, in [`CLAUDE.md`](./CLAUDE.md#not-verified).
- If the original Heracles app (version 0.1) left a library on your PC, it is copied into the new database the first time the app starts. See [Data storage](#data-storage).

## Features

- **Notebooks, sections and pages** in a sidebar, nested as deep as you like, with favorites, archive and trash. Trashing, restoring and deleting apply to a page and everything under it.
- **Panes and tabs.** Split a window right or down, drag the dividers, and drag tabs between panes. Each window remembers its layout, and any number of windows can be open on the same library.
- **Block editor.** Headings, lists, task lists, quotes, callouts, toggles, code blocks, images and column layouts, with the editor's own undo.
- **Markdown as you type**, a slash menu of blocks, and a Format menu with the usual shortcuts.
- **Blocks you can pick up.** Each block has a handle to drag it, make columns with it, duplicate it, turn it into another kind of block, or copy a link to it. Whole blocks can be selected, copied and moved together.
- **Kanban boards.** A todo list is a board with your own columns, which you can rename and reorder. Cards carry notes, priority, a due date, a deadline, labels, a location, reminders, comments and subtasks nested to any depth.
- **Reminders** arrive as Windows notifications, whether or not the app is open. Clicking one opens its list.
- **Search** across every note's title and text.
- **Quick Open** (Ctrl+K) to jump to a note by name.
- **Import and export.** Import Markdown and HTML files as pages, with their pictures. Export a note as Markdown with its pictures beside it.
- **Links between notes.** `heracles://` links open a note, or scroll to one block of it.

Not there yet, here or on the Mac: syntax colouring in code blocks, find within a note, selecting text across blocks, resizing an image, and export to HTML.

| Ctrl+K | Quick Open (with text selected: make a link) |
| Ctrl+W | Close the tab |
| Ctrl+\\, Ctrl+Shift+\\ | Split right, split down |
| Ctrl+B, Ctrl+I, Ctrl+Shift+X, Ctrl+E | Bold, italic, strikethrough, code |
| Ctrl+Alt+0 to 3 | Text, heading 1 to 3 |

| Ctrl+D, Ctrl+Shift+F, Ctrl+Shift+C | Duplicate the note, favorite it, copy a link to it |
| Ctrl+Shift+I, Ctrl+Shift+E | Import files, export the note as Markdown |

## How it is built

| Layer | Choice |
|---|---|
| Interface | C#, WPF on .NET 10 |
| Core | Rust (`heracles-core`): storage, documents, search, import and export |
| Bridge | UniFFI, with C# bindings generated by `uniffi-bindgen-cs` |
| Storage | SQLite with full-text search, bundled into the core |
| Editor | Native: a document model in C#, shown as text blocks with one rich-text box where the caret is |
| Updates | The app's own: a feed on each GitHub release, signed with a key of Heracles' own (ECDSA P-256) and checked with what Windows provides |
| Build | Cargo and the .NET SDK, run by the scripts in `tools\` |

The core owns the data. Every window reads from it and subscribes to its change feed, which is what keeps two windows showing the same note in step. Documents are stored as blocks in JSON, and pictures are stored once each, outside the notes that use them.

## Building

You need, on Windows 10 or 11 (x64 or ARM64):

- Rust, through [rustup](https://rustup.rs)
- Visual Studio 2022 Build Tools with the C++ workload
- The .NET 10 SDK
- `uniffi-bindgen-cs`: `cargo install uniffi-bindgen-cs --git https://github.com/NordSecurity/uniffi-bindgen-cs --tag v0.12.0+v0.32.0`

From PowerShell, in the repository's folder:

```powershell
tools\build.ps1            # the core and its C# bindings, then the app -> build\app\win-<arch>\Heracles.exe
tools\build.ps1 test       # the core's tests (Rust), then the app's (.NET)
tools\build.ps1 run        # start the built app
tools\build.ps1 core package            # a disc image (.iso) and an update archive (.zip) for this PC's processor -> build\release
tools\build.ps1 core package -Arch x64  # and for the other one
tools\build.ps1 feed                    # the signed feed that tells installed copies of them (needs the update key)
```

Run `tools\build.ps1 core` again after any change to the Rust interface: the bindings and the DLL are generated, not kept in git.

The scripts under `tools\e2e` start the built app on a throwaway library and drive its real window. All but the last go through UI Automation, with no mouse and no keyboard:

```powershell
tools\e2e\check-shell.ps1      # the window: sidebar, tabs, panes, search, Quick Open, several windows
tools\e2e\check-editor.ps1     # writing in a note
tools\e2e\check-boards.ps1     # a board and a task
tools\e2e\check-transfer.ps1   # importing files and exporting a note
tools\e2e\check-legacy.ps1     # the first start beside a library of the original app
tools\e2e\check-disc.ps1       # a packaged disc image: opened as a drive, and the app started from it
tools\e2e\check-update.ps1     # a whole update rehearsed on this PC with nothing real in it, and the updates that must be refused
tools\e2e\check-input.ps1      # a minute of real typing, clicking and dragging: leave the mouse and keys alone while it runs
```

`tools\publish.ps1` publishes the packages as a GitHub release, with the feed that installed copies read. Its header says what it checks first.

A release can only be made by whoever holds the update key: every copy takes an update only if the feed was signed with it. `tools\update-key.ps1` says where the key is kept and how to keep a copy of it. A build made without the package step carries no key and never looks for updates.

## Project structure

```
core/                heracles-core: the app's data layer (Rust), shared with the Mac app
app/Heracles/        the Windows app (C#, WPF)
  Model/             the app's view of the library, kept current by the core's change feed
  Workspaces/        panes and tabs
  Sidebar/           the sidebar and Quick Open
  Notes/             a note in a pane
  Editor/            the block editor: its document model, and its views
  Boards/            boards, tasks and reminders
  Updates/           updates over the air: the feed, its signature, fetching and installing
  Icon/              the app icon: its layers, shared with the Mac app, and its compiled forms
app/Heracles.Tests/  its tests
tools/build.ps1      builds, tests and packages
tools/disc-image.ps1 makes the package's disc image, and reads it back
tools/update-*.ps1   the update key, and signing the feed with it
tools/make-icon.ps1  draws the icon again after a change to its layers
tools/e2e/           the scripted checks of the real window
tools/publish.ps1    publishes a release
docs/                the design, the implementation plans, release notes
CLAUDE.md            working notes: decisions, conventions, what is and is not verified
VERSION              the app's version
```

## Data storage

The app keeps everything in `%APPDATA%\Heracles\`:

| Path | Holds |
|---|---|
| `heracles.db` | Notes, documents, boards and the search index, in SQLite |
| `images\` | Pictures, one file each, named by their content |
| `backups\` | The copy made of an earlier library before it was imported |
| `windows.json` | The windows that were open, and their panes |

Its log is `%LOCALAPPDATA%\Heracles\heracles.log`. Beside it, in `updates\`, is what the app remembers about updates and what it has downloaded of one.

The original Heracles app (version 0.1) kept its library in the same folder, in `heracles.sqlite`. The first time the app starts and finds that file, it copies it into `backups\`, reads the copy, and brings the library into `heracles.db`. The old file is never changed.

At its first start the app also tells Windows, for your account only, that `heracles://` links are its to open and that it has notifications to deliver (two keys under `HKEY_CURRENT_USER\Software\Classes`). Nothing needs an administrator.

To try the app on a different folder, start it with `HERACLES_DATA_DIR` set. Started that way it leaves your links and notifications alone:

```powershell
$env:HERACLES_DATA_DIR = "$env:TEMP\heracles-trial"; build\app\win-arm64\Heracles.exe
```
